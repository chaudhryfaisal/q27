# Plan: M2 paged KV (batched-decode spec section 3b), staged M2a/M2b

Deliverable of docs/plans/2026-08-15-batched-decode-spec.md stage M2.
Sources: full 6-lens KV-surface recon 2026-08-16 (workflow wf_1fc3fba0-8d5
journal; line-cited). Staging follows the M0/M1 ground rule: every stage
closes with a measurement and is independently revertible.

## 0. Recon facts the design rides on

- **max_ctx is DEAD in every decode kernel** ((void)max_ctx, spec3.cu:820,
  :1027; fdmma legs never receive it). Per-lane lengths already arrive as
  device loads (IP3 pos; seq = *pos.p[t]+1). The kernel conversion is
  therefore ADDITIVE (a table pointer), not a semantic replacement.
- **Every KV access is single-row arithmetic** off a raw base:
  scalar off = p*rowlen + i, block idx = p*n_kv_heads*2 + h*2 + g. No load
  instruction ever spans two position-rows (recon: prefill PROVEN, decode
  enumerated). Page = 64 rows divides every access pattern.
- **All MMA position tiles are PP=32-aligned** (splits round p_lo to PP
  multiples; empty splits sentinel out) -> a tile never crosses a 64-row
  page; one table lookup per tile. fd2/v1 address per position -> one
  dependent load per iteration (one page spans 16 iterations/warp;
  hoistable if the depth rig says so).
- **Capture discipline**: the mask-pool pattern (fixed device table
  POINTER baked into graphs, mutable ENTRIES) is already in-tree
  (engine.cuh d_mask_pool/d_mask_ids). gc_guard compares pointers only --
  entry rewrites cannot trip it; the MIRROR WARNING at conductor.h:465
  applies only if a table field ever enters the union view (it does not:
  KV is member-only state, build_union_view carries no KV).
- **Persistence**: pfx blobs rely on head-of-buffer contiguity today; the
  on-disk layout stays LINEAR (portable across pool geometries) and the
  export/import walks become per-page copies. MTP rows are [0, L+1) --
  one longer than attention (mtp_warm_T stores at base+1); page pinning
  math must use L+1 on the MTP pair.
- **Admission funnel**: claim_slot is the single point where prompt+n_max
  are both known; entitlement = prompt + n_max + ctx_round_reserve() - 1
  <= cap. FIFO wait = the existing route_cv loop. Pages must belong to
  the SLOT LINEAGE, not the request (tier-2 reuse routing + snap/ckpt
  validity depend on attention rows surviving between requests; the R1
  aliasing finding is the failure class if pages are remapped without
  clearing the reuse tiers).

## M2a: block-table addressing under identity mapping (kernels half)

NO allocation changes. Each engine keeps its per-layer kcache/vcache +
mtp allocs; a per-engine device table maps page j of pair ci to
base + j*64*row_bytes (identity). Kernels stop receiving raw bases and
receive the pair's table slice instead. Bitwise by construction under
identity -- and provably load-bearing via the scatter gate (below).

Table geometry (single kv_kind per boot; K and V row bytes differ):
- npages = ceil(max_ctx / 64); pairs = kcache.size() + 1 (MTP is pair 16).
- ONE device alloc per engine: `void** d_kv_tab`, layout
  [2][pairs][npages] (K half then V half), entries = page base pointers.
  Uploaded at init after the KV allocs; POINTER is init-fixed (baked into
  graphs), entries rewritable between rounds (M2b remaps; M2a identity).
- Kernel-side: ktab = d_kv_tab + ci*npages; vtab = d_kv_tab +
  (pairs + ci)*npages. Row base = (char*)tab[p>>6] + (p&63)*row_bytes;
  block index = (block*)tab[p>>6] + (p&63)*n_kv_heads*2 + h*2 + g.

Conversion checklist (recon-enumerated, exhaustive):
- wrappers grow (k_tab, v_tab) and drop (kc, vc): kv_store, attn_decode
  (blocks.cuh), kv_store3/kv_store_t3/attn_decode3/attn_decode3_fd2
  (spec3.cuh), kv_store_T/kv_store_T_t3/attn_prefill_T (prefill.cuh),
  launch_fdmma/launch_fdmma_h16 (internal).
- kernels: k_kv_store (blocks.cu), k_kv_store3/k_kv_store_t3, fd2 pair,
  k_attn_fd v1 (spec3.cu), k_attn_fdmma + h16 (fdmma.cuh), k_kv_store_T/
  k_kv_store_T_t3, f16-MMA/fp8q/pv8/lite prefill kernels (prefill.cu).
  Addressing-only: identical loop structure, identical fp order, identical
  zero-fill/sentinel semantics (the bitwise contract).
- call sites: attn_block, attn_mix, mtp_attn, attn_block_T, mtp_warm_T
  (engine.cuh); test_kernels.cu call sites get a test-local identity
  table helper.
- persistence: pfx_export/pfx_import switch to per-page walks through the
  table (blob layout unchanged); --kvstats/--pfdbg gather via the same
  helper.
- memsets on mtp_k/mtp_v (init/reset/warm) stay direct (identity M2a) and
  move behind a table walk in M2b.

Scatter gate (the proof the tables are real): Q27_KV_SCATTER=1 (debug
env, read at init) permutes each pair's page mapping with a fixed LCG
before upload. Rows land physically scattered inside the same allocs.
Gate: canonical EXACT must STILL hold (addressing correct under
non-identity), fused_smoke leg A must hold. pfx/persist run through the
table so they survive scatter too.

M2a gates (pre-declared):
1. canonical EXACT a2982c51 (identity AND Q27_KV_SCATTER=1), all-tier
   sweep via tools/canonical_md5.sh keys.
2. fused_smoke all legs x {fp16, fp8, turbo3}; test_kernels (call sites
   updated); turbo3/turbo5/i8g64 codec tests untouched-green.
3. ptxas 0 spills on every touched kernel (P10 gate).
4. PERF (the spec's named risk): tools/attn_fdw_bench.cu fd2 legs at 26K
   and 61K, W in {2,4,8,12}, before/after (the tool forks fd2 verbatim --
   re-point its fork at the paged kernel or mirror the change). Bar:
   paged fd2 within noise (<= ~2%) of contiguous at 61K; fdmma picked up
   automatically via the fdmma.cuh include. Serving-level corroboration:
   tools/width_curve.sh sfxm/sfxn before/after.
5. Single-stream CLI A/B vs pre-M2a binary (canonical prompt, -n 512):
   <= 1% regression.

## M2b: pool + entitlement admission (policy half)

After M2a's tables are proven: one process-wide K-pool + V-pool allocated
beside the shared weights (before ANY capture; sized by the auto-ctx
arithmetic with the per_tok*n_slots divisor removed), page free-list,
claim_slot reserves+maps prompt + n_max + ctx_round_reserve() - 1 rows
per pair (MTP +1) with FIFO wait on route_cv; pages owned by slot
lineage, released only on lineage takeover (tier-0/1 claim) with
snap/ckpt/pfx-RAM tiers cleared first (the R1 rule); continuation =
atomic reserve-extend under route_m or release-and-requeue. Doomed and
cancelled requests release without stranding. max_ctx survives as the
per-slot entitlement CAP only. Estimator: kvb terms leave the slot-skip
`need`; pool line replaces per_tok carve. Gates: admission behavior suite
(C=4@32K admits on 32 GB, oversized 400s not FIFO-stuck, continuation
growth, doomed release), fused_smoke, ladder C=1/2/4 rerun, soak.

## Non-goals (unchanged from the spec)

Cross-sequence attention batching (ruled 2026-07-14), the conductor
graph-key collapse (M4), GDN seq-dim kernels (M5), eviction/preemption of
held pages (FIFO waits instead -- spec section 3b).
